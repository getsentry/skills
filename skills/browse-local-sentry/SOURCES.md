## Decisions

- Adopted: probe trust with curl, then route with `openssl verify` of the
  served certificate against the local mkcert CA. curl's wording does not tell
  the fallback from an untrusted CA, and the issuer string cannot tell two mkcert
  CAs of the same user apart.
- Adopted: keep the checks and safety rules in `SKILL.md`, and the failure
  procedures in `references/troubleshooting.md`, since a working setup needs
  only the checks.
- Adopted: run Step 2 outside shell sandboxes, which hide the keychain from curl
  and may block openssl's direct connection.
- Adopted: change MCP config only with the user's approval, since it persists,
  and pin the server version, since it controls a signed-in browser.
- Adopted: detect a failed openssl capture with `[ -s "$f" ]`, since LibreSSL
  and OpenSSL word the failure differently.
- Adopted: ask for the org instead of using the bare `dev.getsentry.net` host,
  which can land in an arbitrary org under a staff session.
- Adopted: the agent may create a local devserver account, since it only
  touches the local database.
- Rejected: a runtime pointer from `pr-screenshots`, since skills must not
  require each other by name. This skill's description triggers on the same
  certificate and login errors.

## Validation Log

- 2026-10-22: Steps 3 and 4 run against a live dev-ui. `list_pages` listed the
  user's tabs; `/api/client-config/` returned `isAuthenticated: true` over a
  secure context, on both the org subdomain and the bare host.
- 2026-10-22: With a trusted certificate, the service-worker SSL console message
  did not appear, so it is treated as a sign of an untrusted certificate.
- 2026-10-22: A fresh headless Chrome profile loaded dev-ui without certificate
  errors, confirming the mkcert CA is trusted machine-wide.
- 2026-10-22: `/usr/bin/curl` returned 200 against the trusted dev-ui.
- 2026-10-22: curl's message for dev-ui's fallback certificate differed between
  tests: "unable to get local issuer certificate" for a cert generated by
  `@rsbuild/plugin-basic-ssl`, "self signed certificate" for a hand-made
  `CN=localhost` cert. An untrusted mkcert CA gives the former too.
- 2026-10-22: `openssl verify` against `$(mkcert -CAROOT)/rootCA.pem` returned
  `OK` for the live dev-ui's certificate and failed for a self-signed
  `CN=localhost` certificate and for one from a scratch mkcert CA with the same
  issuer string. Expiry reads `certificate has expired` on both OpenSSL 4 and
  macOS LibreSSL. An unreachable port prints different errors on each.
- 2026-10-22: `@anthropic-ai/sandbox-runtime` 0.0.81's default config blocks the curl probe to
  loopback with "CONNECT tunnel failed, response 403". With loopback allowed,
  sandboxed `/usr/bin/curl` rejects the trusted certificate because the sandbox
  denies `com.apple.trustd.agent`, while openssl still connects and verifies
  `OK`. mkcert then reports the CA as already installed, which the `OK` row
  uses to detect the sandbox.
